# 竞品分析与对抗性评审

## 1. 评审方法

本评审不是寻找可复制页面，而是比较不同产品分别优化了什么，并反推 WoWAnalyzerCN 应拒绝什么。研究对象包括本地 Threechest 源码、Keystone.guru、Method Ability Tracker、Icy Veins/Wowhead 类长文攻略、Raider.IO 路线/回放能力，以及 Blizzard 当前 S2 设计信息。

## 3. Threechest 深度结论

### 3.1 值得参考的领域思想

Threechest 将 `Pull` 表达为 `SpawnId[]`，并从 Dungeon 的 mob/spawn 基础数据推导每波 forces、血量和累计进度。地图中 Pull outline 与侧边 Pull list 共享选中状态。这个抽象比“Pull 只写 NPC 类型和文字说明”可靠，因为同一种怪在不同位置、不同组合中会产生不同风险。

可转化为 WoWAnalyzerCN 自研方案的思想：

- 使用稳定、内部生成的 spawn ID。
- Route 只持有 spawn 引用和教学元信息，基础敌人事实不重复。
- forces、怪物组成、首次出现位置、技能集合从引用关系推导。
- 地图与列表使用相同的 resolved view model。
- 任何发布版本都带 manifest/version，部分数据失败时不更新 current 指针。

### 3.2 不应搬运的部分

- GPLv2 代码与 WoWAnalyzerCN AGPL 工程的组合并不自动等于“无风险”；更重要的是用户已经选择独立实现，代码层不应复制。
- Threechest 数据由 MDT 子模块解析而来，数据与图片的独立授权不能仅由 Threechest 的代码许可证推出。
- 当前数据是 Midnight S1，不是本项目目标 S2。
- `enemyIndex-spawnIndex` 会受上游顺序变化影响，不够稳定。
- 类型中缺少明确 floor ID，地图实现以固定 tile/bounds 为中心，难以直接承担多楼层知识模型。
- Redux undo、persist、collab、drawings、notes、imports 是编辑器成本，不适合只读学习域。
- `any`、JSON 强转和运行时纠错不符合本项目的数据质量目标。

### 3.3 可以参考图片完成开发吗

可以将其作为**本地、短期、不可分发的远程视觉夹具**，但不能把“先开发”理解为可以进入仓库或部署环境。项目所有者已确认本地开发可直接加载 Threechest 在线图片，必须满足：

- Threechest URL 只存在于 gitignored 的本地 manifest/`.env.local`，Git/CI/生产构建产物均不可见。
- 通过 `remote-dev` provider 显式开启；生产构建强制使用 OSS provider 或占位图。
- 不用于线上测试站、公开截图、演示视频和 PR 截图。
- 只允许 `localhost` 浏览器直接请求远程图片，不建立绕过来源站限制的代理或缓存镜像。
- 一旦拿到正规资源，替换只改 manifest/provider，不改业务数据和组件。

这解决的是开发节奏，不解决图片版权。生产发布门仍然必须单独通过。

## 4. 产品差异化机会

现有产品常把用户留在两个极端：

- 路线工具告诉用户“拉哪些怪”，但不确保他理解技能组合。
- 攻略数据库告诉用户“每只怪会什么”，但不确保他知道在第几波如何决策。

WoWAnalyzerCN 的机会是把两者连接成可学习的最小单位：

```text
具体 Pull
+ 空间位置
+ 关键怪物组合
+ 动作优先级
+ 失败后果
+ 角色职责
+ 一句话记忆
+ 主动回忆
```

真正的差异化必须收窄为：**中文 + 稳定场景与具体路线关联 + 角色/能力提示 + 主动回忆 + 未来战后日志回链**。单纯“路线 + 技能解释”已经被 Method、视频和新型快速学习站点覆盖。

知识不能用某条路线的 Pull 编号做主锚点。应使用区域/地标/怪物组合/危险模式构成的稳定 Situation，再由 Route Pull 引用、合并或拆分它。

## 5. 对抗性攻击与决策

### 攻击 1：页面最后还是会变成数据库

**风险**：Enemy/Ability/Boss 数据一多，团队容易以“覆盖率”为成就，默认页逐渐堆满卡片。

**决策**：学习页每个 Pull 默认只允许 3～5 个关键机制；完整列表只能从“查看全部技能”进入。内容 Schema 区分 `decisionCritical` 与 `referenceOnly`，发布校验检查高危 Pull 是否有记忆句和行动建议。

### 攻击 2：地图会吞掉产品重心

**风险**：地图看起来最“像功能”，实现团队容易先做 pan/zoom/marker，最后攻略只是右侧说明。

**决策**：默认页先展示 5 分钟速览；逐波学习使用“内容主栏 + 上下文地图”，路线页才让地图占主要空间。Phase 顺序把 Study 骨架放在高级地图交互之前。

### 攻击 3：一条默认路线不适合所有层级和队伍

**风险**：用户把推荐路线当绝对最优，高层路线反而增加普通队伍风险。

**决策**：首版路线明确标注“学习/集合石友好”、目标层级、需要的能力和风险标签；不声称最优。支持后续增加精选变体，但不在首版做路线市场。

### 攻击 4：角色过滤会隐藏团队责任

**风险**：DPS 只看 DPS 内容，不知道治疗压力和坦克路线；学习被切碎。

**决策**：通用动作、失败后果永不隐藏；角色过滤只高亮对应职责并折叠非本职责进阶建议。

### 攻击 5：自测可能成为无聊考试

**风险**：强制题量或分数会阻断快速复习。

**决策**：检查点短、可跳过、无排行榜；只围绕行动决策，不考 NPC ID、数值和冷知识。结果直接链接薄弱 Pull。

### 攻击 6：S2 热修让攻略迅速过期

**风险**：高质量文字本身会造成虚假信任。

**决策**：Knowledge 记录适用 patch、verifiedAt、sources；raw 与 knowledge 分别版本化。版本差异使知识进入 `stale`，页面显示警告但不直接删除。

### 攻击 7：八本内容成本远大于代码成本

**风险**：架构完成后团队仍无法长期维护 8 本 × Pull × 技能 × 角色建议。

**决策**：Ruby Life Pools 垂直切片必须实测作者工时；对每个 Pull 使用统一模板；自动生成事实和反向引用，只人工写决策性知识；允许其余副本以诚实完成度逐步上线。

### 攻击 8：为了“未来 WCL 闭环”过早污染分析系统

**风险**：把 DungeonRunAnalyzer 接口塞进现有 parser，制造上游同步和复杂度。

**决策**：当前只共享稳定知识 ID 和导航 URL。未来事件匹配通过独立 adapter 读取 resolved knowledge，不让攻略域依赖 parser 内部对象。

### 攻击 9：临时资源不小心进入生产

**风险**：开发 fixture 被 import 或复制到 public，CI 未感知。

**决策**：临时资源 URL 只能从 gitignored 的本地配置读取；production build 在 remote-dev mode 下直接失败；CI 检查禁止 Threechest/MDT 资源 URL 和哈希出现在产物。

### 攻击 10：现代化被理解为大量玻璃卡片和动画

**风险**：页面与 WoWAnalyzerCN 割裂，信息密度下降，办公室场景显得像娱乐网站。

**决策**：现代化来自清晰层级、排版、状态、响应式和细节，不来自渐变/发光滥用。使用少量 surface 层级、稳定金色强调、语义色和克制动效。

### 攻击 11：回归副本样本制造虚假的学习成功

**风险**：RLP 测试者可能已有旧版本记忆，完成任务不代表产品教会了他。

**决策**：RLP 负责完整工程切片；Altar of Fangs 再做 3 个 Critical Situation + 1 个 Boss 的小型学习样本。只有新旧样本都通过即时/延迟回忆测试才扩到八本。

### 攻击 12：角色建议把能力责任错误推给某类角色

**风险**：“治疗驱散”“DPS 打断”并非总是成立，队伍职业能力不同。

**决策**：角色只改变信息优先级；具体动作优先写“可解诅咒者”“有进攻驱散的玩家”“分配的第一打断”。用两个能力差异明显的职业做内部 Schema 测试，不把 DK 样例作为用户功能。

### 攻击 13：八本空壳损害可信度

**风险**：可点击但内容建设中的页面让用户形成“站点没内容”的第一印象。

**决策**：赛季中心可展示八本覆盖路线图，但只有 `reviewed`/`published` 开放正式入口。未完成副本不可伪装为可学习产品。

## 6. 替代方案比较

### 方案 A：最小静态攻略

优点：快、风险低。缺点：无法建立长期数据资产，地图、Pull、技能无法互相引用，新赛季仍要重写页面。拒绝。

### 方案 B：先做 Threechest 风格只读路线

优点：视觉成果快、空间认知强。缺点：路线成为默认心智，攻略退化为附注，无法证明 10～15 分钟学习目标。拒绝作为主方案，可作为独立子页面。

### 方案 C：学习优先的结构化知识域

优点：与 WoWAnalyzer 的“Improve”定位一致；可连接 WCL；新赛季主要更新数据和知识；区别于现有路线工具。缺点：需要内容规范、自测和更严格的数据治理。推荐。

## 7. 最终范围判断

### 现在做

- 独立数据/知识域。
- Ruby Life Pools 完整学习闭环。
- 八本注册、完成度与基础数据扩展路径。
- 只读地图与推荐路线。
- 怪物/技能查询和 Boss 学习。
- 本地进度、自测、来源/版本状态。

### 延后

- 第二条路线变体、职业技巧规模化。
- WCL 运行复盘与自动薄弱项。
- 内容反馈后台、多人审校工作台。

### 不做

- 编辑器、协作、社区、AI 自动攻略、Raid。
