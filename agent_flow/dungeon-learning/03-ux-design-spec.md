# UX 与视觉设计规范

## 1. 设计目标

设计应让用户感觉这是 WoWAnalyzerCN 自然长出的“学习工作台”，不是嵌入的另一个站点。现代化主要通过信息层级、排版、状态反馈、响应式和交互细节实现，保持克制的魔兽气质。

关键词：

- 深色、专业、专注。
- 信息密度适中，但不稀疏。
- 金色强调只用于当前目标、主操作和标题。
- 机制色用于语义，不能取代文本。
- 地图是上下文，不是所有页面的背景。
- 办公室可用：无自动视频、无夸张首屏、无持续闪烁。

## 2. 与现有主题的连接

现有代码提供了明确基础：

- `Theme.$backgroundColor = hsl(44, 7%, 8%)`。
- `Theme.$panelColor = hsla(44, 3%, 11%, 1)`。
- `Theme.$primaryColor = #fab700`。
- `_design-system.scss` 提供 level 0/1/2 背景、边框、阴影和 0.5/1/2rem 间距。
- Poppins 用于标题，Open Sans 用于正文。
- Guide Data Wrapper 已使用 8px 圆角、轻边框和更现代的数据卡片语言。

Dungeon 模块应复用 token 和字体，不直接复用所有旧 `.panel` 布局。建议新增 Dungeon 自有 CSS module/component，使用现有 design tokens 形成以下层级：

| 层级    | 用途                                     | 视觉                                      |
| ------- | ---------------------------------------- | ----------------------------------------- |
| Level 0 | 页面背景                                 | 现有深色纹理/纯色，避免额外大图           |
| Level 1 | 学习主栏、地图容器、侧栏                 | `$level1_background`、细边框、轻阴影      |
| Level 2 | 当前 Situation、技能行、自测选项、过滤器 | `$level2_background`；激活态带金色边/底线 |
| Overlay | Tooltip、Inspector、移动抽屉             | 更深背景、明确遮罩和焦点管理              |

## 3. 页面骨架

### 3.1 DungeonLayout

`DungeonLayout` 复用 `AppLayout` 和 `NavigationBar`，不套 `HomeLayout` 的 1300px 内容结构。Dungeon header 与 workspace body 使用同一个 scoped 容器和统一 gutter；全局导航继续保持现有壳，不能让标题、章节栏和地图各用不同左边界。桌面 workspace 上限可在 1440～1600px 原型测量后冻结，保留 24～32px 页面边距。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Global Navigation                                                   │
├──────────────────────────────────────────────────────────────────────┤
│ Dungeon header: 名称 / S2 / 更新状态 / 角色 / 全局进度              │
├──────────────┬──────────────────────────────────┬────────────────────┤
│ Chapter rail │ Learning content                 │ Context map        │
│ 60秒/5分钟   │ Situation / Boss / checkpoint    │ 当前场景高亮       │
│ 逐波         │ action-first                     │ forces / floor     │
│ 怪物         │                                  │                    │
│ Boss         │                                  │                    │
└──────────────┴──────────────────────────────────┴────────────────────┘
```

仅在 ≥1440px 使用三栏。桌面学习页推荐列宽：

- 章节栏：220～260px，可折叠。
- 学习主栏：minmax(520px, 1fr)。
- 地图上下文：最多占可用宽度 32%～35%，`position: sticky`，高度不超过 viewport，且用户可折叠。

地图页切换为 55% 地图 + 45% Pull/详情，但仍保留相同 Header、机制标签和排版。

### 3.2 副本列表

不要使用 8 个同质化、巨大图片卡片。建议按“当前赛季 + 学习状态”组织为紧凑列表/卡片混合：

```text
┌──────────────────────────────────────────────────────────────┐
│ Midnight S2 大秘境                         8 个副本 / 1 已发布 │
│ 选择今晚想学的副本；完整学习约 10～15 分钟                    │
├──────────────────────────────────────────────────────────────┤
│ [小缩略图] 红玉新生法池 / Ruby Life Pools                    │
│ 12 Pull · 3 Boss · 8 个关键机制             [继续学习 40%]   │
│ 更新于 8 月 9 日 · 已审校                                      │
├──────────────────────────────────────────────────────────────┤
│ [占位/缩略图] 诸王之眠 / King's Rest                          │
│ 基础数据完成 · 攻略审校中                       [查看基础数据] │
└──────────────────────────────────────────────────────────────┘
```

Dungeon artwork 只是辅助识别，不能承担文字对比背景。图片缺失时使用统一符号/色块占位，布局不跳动。

## 4. 学习页信息设计

### 4.0 一级信息架构

“学习”和“查资料”不能成为四个同权 tab：

```text
学习（默认）
├── 60 秒进本前复习
├── 5 分钟建立全貌
├── 完整学习（10～15 分钟）
└── 薄弱项复习

查资料
├── 只读路线
├── 怪物与技能
└── Boss 资料
```

Boss 教学节点属于完整学习；Boss 资料页只用于反查。首次访问默认进入 5 分钟模式；已有未完成进度时默认“继续学习”。60 秒模式始终可见，但系统不根据时间、设备或 URL 猜测用户是否即将进本。

### 4.1 Header

- 中文名主标题，英文名和 S2 作为次级信息。
- 内容状态：已审校 / 草稿 / 可能过期。
- 角色 segmented control：全部、坦克、治疗、DPS。
- 进度只显示“已掌握 6/12 个关键节点”，不使用夸张经验条。
- 全局主操作最多一个：开始/继续学习。

### 4.2 三种学习体验契约

| 模式     | 内容                                                            | 地图                                     | 完成态                        |
| -------- | --------------------------------------------------------------- | ---------------------------------------- | ----------------------------- |
| 60 秒    | 当前角色/能力相关 3～5 个最高风险动作                           | 不加载完整地图；最多一个可点击地标裁切图 | “今晚先记住这 3 件事”         |
| 5 分钟   | 一句话模型、5～8 个 Critical Situation、Boss 最小动作、路线缩略 | 默认折叠或约占内容区 20%                 | “你已建立全貌；还需复习 N 条” |
| 完整学习 | 按 Situation 推进、路线引用、检查点、薄弱项                     | 上下文地图最多 32%～35%，可折叠          | “今晚进本前再看 3 条”         |

所有模式都没有考试分数、连胜、排行榜和彩纸动画；使用“需要复习”，不用“失败”。

### 4.3 5 分钟速览

布局顺序：

1. 一句话副本心智模型。
2. “今晚先记住”列表。
3. 高危节点时间轴。
4. 角色专属三条。
5. 学习路线概览和 CTA。

“今晚先记住”不是 12 张卡片，而是可扫描的编号清单；点击某条定位到对应 Situation 或 Boss。

### 4.4 Situation Lesson

```text
┌───────────────────────────────────────────────────────┐
│ 双龙平台前                                            │
│ 高危场景 · 当前推荐路线 P03 · +8.4% · 累计 31.2%       │
│ 为什么这样拉：避开巡逻重叠，并为下一场景保留群控。     │
├───────────────────────────────────────────────────────┤
│ 一句话：先杀炎术师，火焰箭雨一定断，龙头背对队伍。     │
├───────────────────────────────────────────────────────┤
│ [必断] 火焰箭雨                                      │
│ 漏断：全队高额伤害；动作：第一优先打断                 │
│ [正面] 灼热吐息                                      │
│ 命中：高伤害+DoT；动作：坦克背对，其他人站侧后方       │
├───────────────────────────────────────────────────────┤
│ 你的职责（治疗）                                     │
│ 第二轮群伤前预铺；漏断时优先驱散目标并开群疗。         │
├───────────────────────────────────────────────────────┤
│ [上一场景] [标记需要复习]                  [下一场景] │
└───────────────────────────────────────────────────────┘
```

视觉规则：

- 稳定 Situation 标题是主标题；当前路线 Pull 编号和 forces 是次要信息。
- 一句话记忆使用浅金色左边框，不使用大面积黄色背景。
- 技能行由图标、技能名、机制 badge、后果、动作组成；所有文字可复制。
- Critical 技能在结构上前置，不能只通过红色表示。
- 当前角色区有清晰标签，但不遮蔽通用动作。

### 4.5 地图上下文

- 默认锁定当前 Situation 覆盖的 spawn/路线段，用户可手动缩放/平移。
- 当前 Situation 使用金色 outline；相邻路线节点低对比显示；危险怪用语义 icon。
- 地图上不同时显示所有技能 badge。
- 点击怪物打开轻量详情；详情再链接完整 Enemy 页面。
- 多楼层用明确 tab/segmented control，切换时保留当前 Situation 的 floor。
- “重置到当前场景”始终可见。
- 60 秒不加载完整地图；5 分钟只显示小型缩略；只有完整学习和只读路线使用完整交互地图。

### 4.6 学习情绪旅程

```text
不知道从哪看
→ 60 秒获得控制感
→ 5 分钟形成副本全貌
→ 在 Situation 中理解原因
→ 主动回忆暴露薄弱点
→ 带着“今晚只需再看 3 条”离开
```

每段有独立、平静的完成态；进度用于恢复上下文，不制造压力。

## 5. 机制视觉语言

机制定义拆为“动作类型”和“严重度”，防止一种颜色同时表达两个维度。

### 5.1 动作类型

| 类型              | 中文标签       | 图形方向          |
| ----------------- | -------------- | ----------------- |
| interrupt         | 必断/打断      | 断开的施法条/闪电 |
| stop              | 硬控打断       | 停止/控制         |
| dispel-friendly   | 治疗驱散       | 十字/净化         |
| purge             | 进攻驱散       | 向外剥离          |
| soothe            | 驱散激怒       | 爪痕/安抚         |
| avoid             | 躲开           | 脚步/区域         |
| frontal           | 正面           | 扇形              |
| tank-buster       | 坦克杀手       | 盾牌裂纹          |
| defensive         | 开减伤         | 盾牌              |
| priority-target   | 优先击杀       | 靶心              |
| spread/stack/soak | 分散/集合/分摊 | 人群空间关系      |
| line-of-sight     | 卡视野         | 眼睛/遮挡         |
| movement          | 移动处理       | 方向箭头          |

### 5.2 严重度

- Critical：红/橙边框 + “致命/必须”文字。
- High：琥珀边框 + “高危”。
- Medium：蓝灰/中性边框。
- Reference：低对比，仅在完整技能页出现。

金色是品牌/选中态，不再用作危险度，避免语义冲突。

## 6. 状态设计

| 状态                   | 用户看到什么                           | 可执行动作                   |
| ---------------------- | -------------------------------------- | ---------------------------- |
| Initial loading        | 稳定骨架屏，保留 Header/列宽           | 无需阻塞全局导航             |
| Map loading            | 内容先可读，地图区域独立 skeleton      | 继续阅读                     |
| Partial knowledge      | 明确“基础数据完成，攻略审校中”         | 查看事实，不显示未经审校建议 |
| Stale                  | 顶部非阻断警告，列出验证 patch         | 查看来源/更新时间            |
| Missing map            | 结构占位 + Situation 列表仍可用        | 使用列表学习                 |
| Tooltip failure        | 静态名称、ID、动作建议仍存在           | 重试 tooltip/打开外部链接    |
| Invalid URL situation  | 回到最接近合法节点并提示               | 继续学习                     |
| Empty filters          | 解释当前筛选无结果                     | 一键清除筛选                 |
| First visit            | 默认 5 分钟模式，解释三种学习时长      | 开始 5 分钟 / 选择 60 秒     |
| Resume                 | 显示上次 Situation 和薄弱项            | 继续学习                     |
| Completed              | 显示需要复习的 0～3 条，而非仅 100%    | 60 秒复习 / 查资料           |
| No weak items          | 平静说明目前无薄弱项                   | 随机主动回忆 / 返回概览      |
| Fingerprint changed    | 仅受影响知识重新进入复习，并解释原因   | 查看变更                     |
| Storage unavailable    | 页面可用但进度不持久化                 | 继续无痕学习                 |
| No role advice         | 通用动作照常显示                       | 切换全部信息                 |
| Situation off route    | 说明该场景不在当前推荐路线，但仍可学习 | 查看出现路线                 |
| Stale advice withdrawn | 保留已验证事实，撤回不可靠建议         | 查看来源/更新时间            |

## 7. 响应式

### ≥ 1440px

三栏学习布局，地图 sticky；路线页双栏。

### 1024～1439px

章节栏折叠为顶部横向导航；主栏 + 地图两栏。地图可折叠，但当前 Situation 的小型位置预览始终可达。

章节栏折叠；主内容 + 可折叠地图，不强制三栏。

### < 1024px

- 单栏内容。
- Header 压缩，角色选择可横向滚动。
- 地图作为固定比例区块或全屏 sheet。
- 底部固定上一场景/下一场景，不遮挡正文。
- Chapter rail 变为可访问抽屉。
- sheet/抽屉必须有焦点锁定、Escape/关闭按钮、关闭后返回触发元素和滚动位置恢复。

移动端目标是可用，不追求把桌面地图编辑体验缩小；因为当前本来也不实现编辑器。

## 8. 交互与动效

- Pull 切换：内容淡入/轻位移 120～180ms；地图平移不超过 300ms。
- hover 不是唯一触发方式，所有详情可点击/键盘打开。
- 自测答错后先解释正确动作，再链接对应 Pull，不使用抖动或负面动画。
- 保存进度即时、本地、无 toast 噪声；只有存储失败时提示。
- `prefers-reduced-motion` 下取消地图飞行动画和内容位移。

## 9. 可访问性验收

- 用键盘从章节栏到 Situation 内容、地图操作、上一/下一场景不丢焦点。
- 选中 Pull 变更后，屏幕阅读器播报 Pull 标题和进度。
- 机制 badge 有可读文本；icon `aria-hidden`，不重复播报。
- 地图提供同等信息的文本 Pull 列表，不能成为唯一信息载体。
- 色盲模式下仍可通过图标、边框样式和标签区分机制。
- 自测题组使用正确 fieldset/legend 或等价语义。

## 10. Dungeon UI primitives

- `DungeonPageShell`：scoped workspace、统一 gutter 与响应式。
- `LearningHeader`：模式、角色/能力、状态和继续入口。
- `LearningSurface`：每页唯一主 Surface，避免 card-in-card。
- `SituationNavigator`：稳定场景序列与路线引用。
- `MechanicRow`：技能、动作、后果，不套独立大卡片。
- `ContextMapPanel`：按学习模式降级、可折叠。
- `Checkpoint`：先回忆/置信度/揭示/返回场景。

这些组件使用现有 token、Poppins/Open Sans 和金色品牌色，但不直接复制旧 `.panel` 与方形大写 `.btn-primary`。正文不低于 14px，辅助文字不低于 12px；不能照搬 GuideDataWrapper 的 1rem 弱提示字号。

反卡片规则：

- 一个视图最多一个主 Surface，边框嵌套不超过两层。
- 桌面怪物查询默认紧凑列表/表格 + 展开行，移动端再转分组条目。
- 分隔线、缩进和留白优先于给每段套卡片。
- “今晚先记住”保持编号清单。

## 11. 常用视口与安静使用场景验收

- 1366×768、1280×720 不出现三栏挤压。
- 默认无声音、无自动视频、无强制全屏、无持续动画。
- 首屏无大幅宣传图，地图/媒体延迟加载，不妨碍先读文字。
- 不弹阻断式新手引导；所有关键文本可复制。
- 基准视口：1366×768、1440×900、390×844。

## 12. 设计评分目标

进入实现前预期粗案评分：

| 维度             | 粗案风险 | 实现验收目标 |
| ---------------- | -------: | -----------: |
| 信息架构         |   6.5/10 |       ≥ 9/10 |
| 学习路径清晰度   |     6/10 |       ≥ 9/10 |
| 与现有主题一致性 |   7.5/10 |       ≥ 9/10 |
| 地图与内容平衡   |     6/10 |       ≥ 9/10 |
| 响应式           |     7/10 |       ≥ 9/10 |
| 可访问性         |     7/10 |       ≥ 9/10 |
| 状态完整性       |     7/10 |       ≥ 9/10 |

实现阶段应先做低保真交互原型，再做三个高保真状态：60 秒复习完成、Critical Situation + 地图、自测答错后回链。用 RLP 与 Altar of Fangs 样本验证，不直接对八本批量套 UI。
