# 大秘境学习模块产品需求文档

## 1. 产品定义

### 1.1 产品名

- 对外候选：**副本学习**、**大秘境攻略**。
- 内部域名：`Dungeon Knowledge`。
- 内部体验名：`Dungeon Coach` / `Dungeon Learning Companion`。

“副本攻略”适合导航入口，进入后使用“学习”作为核心动作。不要用“路线规划器”命名首要入口。

### 1.2 一句话价值

让不熟悉某个大秘境的普通国服玩家，在白天花 10～15 分钟，记住今晚进本真正会影响决策的路线、波次、怪物技能和 Boss 机制。

### 1.3 北极星结果

用户完成一次学习后，能够不看完整攻略回答：

1. 这个副本的大致行进顺序是什么？
2. 每个关键 Pull 为什么这样拉？
3. 这波最危险的怪和技能是什么？
4. 技能漏处理有什么后果，我应该做什么？
5. 作为坦克、治疗或 DPS，我在关键节点的职责是什么？
6. 每个 Boss 最少必须记住哪两到四个动作？

页面浏览量、地图操作次数不是成功标准；“形成可执行记忆”才是。

### 1.4 三种学习时长

“10～15 分钟”不是唯一模式，产品应覆盖三个明确时刻：

- **60 秒进本前复习**：只看本职责/能力相关的 3～5 个最高风险场景。
- **5 分钟建立全貌**：路线结构、Boss 和 5～8 个关键场景。
- **10～15 分钟完整学习**：按场景/路线逐步学习，并完成主动回忆。

网页负责事前建立心智模型；游戏内插件更适合实战时提醒。产品不应与插件争夺“当前 Boss 弹窗”场景。

## 2. 用户与使用场景

### 2.1 核心用户

- 国服普通 M+ 玩家，常用中文信息。
- 时间碎片化的上班族，白天可浏览网页、晚上才能进本。
- 对新赛季副本不熟，无法从长视频中快速提取重点。
- 不一定是坦克或路线作者，但希望理解队伍为什么这样走、这样控、这样交技能。

首版路线和建议的明确假设：

- 面向使用集合石、基础语音/文字沟通的普通队伍。
- 目标是 S2 live 的中低至中等层级学习，具体 key range 在数据稳定后由路线作者填写，不能默认适用于冲层。
- 推荐的含义是“学习友好、容错优先、可复述”，不是速度最优。
- 每条路线和 Critical 建议必须有作者、审校者、目标层级、队伍能力假设和验证版本。

### 2.2 次级用户

- 换职责的玩家：已有副本认知，需要快速查看新职责的注意点。
- 回归玩家：记得旧版本，但不知道 S2 重做/热修后的差异。
- 看直播或复盘日志的玩家：想把某次死亡、漏断和具体 Pull 联系起来。
- 内容维护者：需要可验证、可版本化地维护八个副本。

### 2.3 主要 Jobs To Be Done

| 场景               | 用户真正想完成的任务           | 当前替代方案的阻力               |
| ------------------ | ------------------------------ | -------------------------------- |
| 第一次打某本前     | 快速建立空间与机制心智模型     | 长视频耗时；静态长文难与路线对应 |
| 开组/进本前 3 分钟 | 复习最危险的 Pull、打断和 Boss | 数据库太全，重点不突出           |
| 换职责             | 只看本职责的动作               | 通用攻略缺乏角色分层             |
| 打完出错后         | 回到对应波次复习               | WCL、路线和攻略彼此割裂          |
| 新赛季更新         | 快速替换基础数据和重审知识     | 复制粘贴文档难发现失效引用       |

## 3. 产品原则

1. **动作优先于百科**：优先回答“我该做什么”，再提供原始技能信息。
2. **稳定场景优先于孤立对象和 Pull 编号**：技能只有放到区域、地标、怪物组合和危险模式里才有实际意义；某条路线的 P07 只是一个引用，不是知识主键。
3. **渐进披露**：默认只展示关键内容，完整技能库放在查询页。
4. **解释路线，不生产路线**：说明为什么这样拉，不提供编辑器。
5. **主动学习，不止阅读**：学习结束必须有自测和薄弱项复习。
6. **证据与版本可追踪**：每条关键知识知道来源、验证时间和适用版本。
7. **中文优先、稳定 ID 驱动**：展示中文，底层使用 Dungeon/NPC/Spell/Spawn ID。
8. **缺失比臆造更好**：无可靠攻略时显示“建设中”，不自动生成看似完整的建议。

## 4. 范围

### 4.1 Midnight Season 2 副本池

以 Blizzard 当前公布并持续热修的 S2 数据为准，规划注册以下八个副本：

1. Altar of Fangs
2. Murder Row
3. Den of Nalorakk
4. The Blinding Vale
5. Voidscar Arena
6. King's Rest
7. Ruby Life Pools
8. Temple of Sethraliss

副本池与机制仍可能在 PTR/热修阶段变化，数据必须包含 patch/版本状态，不在组件中写死列表。

### 4.2 MVP 必须完成

范围分为三道门，避免“所有东西都是 MVP”：

**学习原型**：

- Ruby Life Pools 3～5 个关键场景 + 1 个 Boss。
- Altar of Fangs（全新 S2 副本）3 个关键场景 + 1 个 Boss。
- 60 秒/5 分钟入口、最小主动回忆、角色与能力表达。
- 目的是验证新玩家能否学会，不承诺发布完整副本。

**发布 MVP**：

- `/dungeons` S2 学习中心。
- Ruby Life Pools 完整工程和内容垂直切片。
- 默认学习、只读推荐路线、基础怪物反查、Boss、进度与薄弱项。
- 中文回退、tooltip、错误/缺失状态、数据验证和按本懒加载。
- 只有达到 `reviewed` 的副本可进入正式学习；未完成副本只在赛季覆盖路线图中显示。

**Season Pack**：

- 按审校节奏逐本发布其余七本，而不是八个空壳同时上线。
- 从副本页进入现有日志分析入口的轻连接放在发布后期。

### 4.3 明确不做

- Route Editor、拖拽怪物、画线、MDT 导入导出。
- 用户上传路线、协作、社区、评论、点赞、排行榜。
- 云端账号进度同步。
- Raid、完整 DungeonRunAnalyzer、WCL 自动生成路线。
- AI Chat、抓取网页后自动发布攻略。
- 全职业/全专精建议；首版只保留数据结构，最多用 Death Knight 做少量验证。
- 自动播放视频或以视频作为主要学习媒介。

## 5. 信息架构

```text
/dungeons
└── Season 2 学习中心
    └── /dungeons/:slug（仅 reviewed/published 正式开放）
        ├── 学习（默认）
        │   ├── 5 分钟速览
        │   ├── 逐波学习
        │   ├── Boss 节点
        │   └── 自测与薄弱项
        ├── 路线（只读）
        ├── 怪物与技能
        └── Boss
```

实现可以使用 nested routes，也可以在同一 lazy route 内用子路由组织，但 URL 必须可分享并能恢复所选 Pull、角色与章节。

推荐 URL：

```text
/dungeons/ruby-life-pools/learn?mode=full&situation=rlp-upper-ring-casters&role=healer
/dungeons/ruby-life-pools/route/rlp-phase1-learning-route
/dungeons/ruby-life-pools?query=interrupt
/dungeons/ruby-life-pools/boss/rlp-phase1-boss-melidrussa
```

这些路径对应当前只读实现：学习页使用 `learn`，路线/Boss 使用稳定实体 ID，查询入口暂时集中在副本 Inspector；后续若引入兼容别名，必须由路由层 canonical redirect 到稳定路径，不能让内容数据依赖旧 URL。

## 6. 核心学习体验

### 6.1 副本首页 / 5 分钟速览

进入副本默认显示学习摘要，而不是大地图：

- 预计学习时间。
- 路线 Pull 数、Boss 数和楼层/区域数。
- “今天先记住这 8～12 条”。
- 高危 Pull 时间轴。
- 必断、必躲、驱散、坦克杀手的数量摘要。
- 角色选择：全部 / 坦克 / 治疗 / DPS。
- 新赛季或热修变化提示。
- CTA：开始逐波学习；次要动作：打开只读路线、查询怪物。

验收：首次用户在 30 秒内能找到“从哪里开始”和“这个本最难的是什么”。

### 6.2 场景与逐波学习

知识首先锚定稳定的 `Situation / Encounter Segment`，如“二号 Boss 前楼梯双法系组”；推荐路线再说明它在当前路线中是 P07、被合并还是拆分。这样用户换路线后仍能识别危险组合。

根据场景类型使用分级模板，避免每波都变成长文：

- **Routine**：一句话、怪物组合、一个关键动作。
- **Critical**：完整位置、原因、动作、后果、职责、记忆句与自测。
- **Transition / Skip / Event**：移动、触发、视野、跳怪、事件规则与失败恢复。
- **Boss**：阶段/循环模板。

Critical 场景按统一顺序回答：

1. **位置与目标**：当前在哪里，走向哪里。
2. **为什么这样拉**：安全、节奏、Boss 门槛、forces、跳怪或技能组合原因。
3. **怪物组成**：以危险度排序，而不是按 NPC ID。
4. **关键技能**：默认最多展示 3～5 个会改变玩家决策的技能。
5. **处理方式**：明确的动词，如“打断、停手、驱散、背对、分散、开减伤”。
6. **失败后果**：说明为何重要，避免只有标签。
7. **角色职责**：只突出当前角色的特殊任务，通用动作仍保留。
8. **一句话记忆**：可复述、可自测。
9. **可选进阶**：高层、特殊职业技巧、路线变体，默认折叠。

每个路线节点支持上一节点/下一节点、地图定位、标记“已掌握/需要复习”和键盘导航。页面标题优先显示稳定场景名，路线 Pull 编号作为次级信息。

### 6.3 怪物与技能

不是将所有 tooltip 平铺，而是提供查询模式：

- 搜索中文/英文怪物名、技能名、NPC ID、Spell ID。
- 筛选：高危、必断、可硬控、进攻驱散、治疗驱散、激怒、正面、坦克杀手、全团伤害、优先击杀。
- Enemy Card 展示：中文名、英文名、NPC ID、forces、危险度、出现 Pull、关键技能。
- Ability 展示：事实属性、玩家动作、失败后果、角色差异、首次出现 Pull、来源与更新时间。
- 点击技能复用现有 `SpellLink`/tooltip；tooltip 失败时保留静态名称和动作建议。

### 6.4 Boss 学习

每个 Boss 按“阶段/循环”组织，不做完整时间轴：

- 开场一句话心智模型。
- 每阶段 2～5 个关键机制。
- 技能顺序只在会影响准备时表达。
- 角色职责和团队协作。
- 常见团灭原因。
- 一句话自测题。

### 6.5 学习闭环

被动阅读不会自动转化为记忆，MVP 必须有低成本的主动回忆：

- 每 3～5 个关键场景插入一次“检查点”。
- 先让用户无选项回忆或自报“想得起来/有点模糊/完全忘了”，再揭示答案；选择题只作为辅助。
- 题型优先选择“看到怪物图标/模拟施法条后说出动作”“这个组合先处理谁”“漏断后果是什么”。
- 错题记录在 localStorage，学习完成后只复习错题和标记薄弱 Pull。
- 支持次日延迟复习；不要求账号，由稳定知识 ID + 内容指纹决定是否重新进入复习。
- 首版至少提供接近实战的视觉刺激：怪物/技能图标、模拟施法条、地图局部。授权明确后可增加用户主动播放的 3～6 秒循环片段，但不自动播放，也不作为 MVP 阻塞项。
- 自测不做分数排行榜，不制造考试压力；显示“今晚进本前再看 3 条”。

## 8. 内容完成度模型

每个副本必须显示真实状态：

```text
registered → raw-ready → route-ready → knowledge-draft → reviewed → published → stale
```

- `registered`：仅在赛季覆盖路线图展示，不提供正式学习入口。
- `raw-ready`：地图、spawn、怪物、技能事实完成并通过校验。
- `route-ready`：至少一条只读学习路线通过 forces/引用校验。
- `knowledge-draft`：已有人工攻略但未双人审校。
- `reviewed`：核心场景、Boss 和高危技能完成审校，可开放正式入口。
- `published`：满足发布质量门。
- `stale`：游戏版本高于知识验证版本，仍可查看但明确警告。

## 9. 非功能需求

### 性能

- `/dungeons` 只加载 season manifest 和卡片摘要。
- 进入副本后才加载该副本的 raw、knowledge、路线和地图。
- 地图资源延迟到地图进入视口或用户打开路线/波次时加载。
- 大量 spawn 不应触发全页重渲染；选中 Pull 只更新必要图层。
- 首版不为地图性能引入复杂全局状态或 WebGL。

### 可访问性

- 机制不能只靠颜色区分；标签同时包含图标和文本。
- 键盘可完成切换 Pull、角色、章节和自测。
- 焦点清晰，触摸目标至少 44px。
- 正文和次要文本满足 WCAG AA 对比度目标。
- 减少动态效果偏好下关闭非必要动画。

### 可靠性

- 单个技能 tooltip、中文名称或地图资源失败不会让整本攻略崩溃。
- 无合法生产地图时显示结构化占位区，不回退到未授权临时图片。
- 数据解析失败在构建/校验阶段阻断，而不是到用户浏览时才发现。

## 10. 产品指标

首版以行为和定性验证为主：

- 首次有效信息时间：进入副本后 30 秒内打开一条关键知识。
- 学习启动率：进入副本页后开始逐波学习的比例。
- 学习完成率：完成速览 + 至少 70% 关键 Pull。
- 主动回忆率：至少完成一个检查点的比例。
- 薄弱项复习率：错误后打开对应 Pull/技能的比例。
- 内容可信度：用户反馈“过期/错误”数量、修复时间。
- 维护成本：新增一个普通 Pull 的中位耗时、新赛季八本更新总工时。
- 即时无提示回忆正确率、24 小时延迟回忆率。
- 新玩家/回归玩家分组结果，以及与当前长文或视频方案的对照任务差异。
- stale 内容曝光率、错误报告/千次内容曝光、热修到修订的延迟。

禁止用“地图点击次数”和“停留越久越好”替代学习成效。

## 11. 发布验收

学习原型先用小样本发现问题；正式发布前扩大到至少 8～12 名目标用户，并区分首次接触与回归玩家。除 RLP 外，使用 Altar of Fangs 小样本验证全新副本学习，避免旧记忆抬高成绩。任务包括：

1. 找到第三个高危 Pull。
2. 说出这波第一优先怪和必处理技能。
3. 切换到自己的职责并复述动作。
4. 完成对应自测。
5. 关闭并重新打开页面，继续学习。

成功标准不只看能否操作页面，还比较即时/延迟无提示回忆与现有长文/视频基线。具体阈值在原型测得基线后冻结；在此之前不得用“完成页面”宣称“已经学会”。
